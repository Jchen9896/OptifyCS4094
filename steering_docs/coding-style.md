## Coding Conventions 

When building features in this repository you **MUST** adher to the following coding conventions. If there is a deviation you must explain why.

1. When making a change or feature update you should only make incremental reviewable changes to the order of up to 200 lines of source code and 200 lines of test code. You should also only edit up to a maximumize of 3 files, but this can be overrules if the total number of edits is less than 200 line. You must also provide reasoning if more than 3 files are edited and/or if 200+ lines of source code and tests are in a cr. 

2. You **MUST** adher to SOLID coding principles.

3. You should use dependency injection whenever possible with a focus on testibility, maintainability, and decoupling. 

4. **DO NOT** hard code anything. 

5. Generated code should be simple and understandable. **DO NOT** use any complex tricks without a clear explaination for doing so. 

6. Explanations **MUST** be in ASD-STE100 Simplified Technical English. 

7. Commits should **ALWAYS** follow steering_docs\commit-style.md

8. Any significant or key architectural decision or finding **MUST** be added to steering_docs\decisions.
